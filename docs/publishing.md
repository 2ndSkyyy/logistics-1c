# Публикация через GitHub Desktop

Для исходников нужен обычный Git-репозиторий с распакованными файлами. ZIP используется для передачи комплекта; помещать его внутрь репозитория не требуется.

## Создать локальный репозиторий

1. Скачайте подготовленный ZIP, распакуйте во временную папку. Внутри `logistics-1c` должны быть `README.md`, `src`, `docs`, `examples`, `tools` и служебные файлы Git.
2. В GitHub Desktop войдите в свой GitHub через **Sign in to GitHub.com**. Пароль и коды вводите только в открытом окне входа GitHub.
3. Выберите **File → New repository…**. Заполните:

| Поле | Значение |
|---|---|
| Name | `logistics-1c` |
| Description | `Учебная конфигурация 1С: заявки на перевозку, обмен JSON с Бухгалтерией и контроль оплат.` |
| Local path | Например `E:\GitHub\publish` |
| Initialize this repository with a README | Не отмечать: README уже подготовлен |
| Git ignore | `None`: свой файл есть в комплекте |
| License | `None`: выбор лицензии отложен |

GitHub Desktop создаст вложенную папку `E:\GitHub\publish\logistics-1c`. Путь `Local path` — это родительский каталог. Так новая папка не смешается с ранними ошибочными выгрузками.

4. Нажмите **Create repository**.
5. Откройте созданную папку через **Repository → Show in Explorer**. Скопируйте в неё **содержимое** папки `logistics-1c` из архива, включая `.gitignore` и `.gitattributes`. Не создавайте ещё одну вложенную `logistics-1c`.
6. Проверьте расположение: `README.md` и каталог `src` должны лежать сразу в корне. Архивов, `.dt`, `.1CD`, полной типовой Бухгалтерии здесь быть не должно.

## Зафиксировать и опубликовать

1. Примените и проверьте три исправления по [prepublication.md](prepublication.md), обновите исходники и отметки тестов. Если публикуете до выполнения проверок, оставьте в README текущий честный статус «для проверки перед первым выпуском».
2. В GitHub Desktop откройте **Changes**. Просмотрите список изменений. В `src/bp-extension/Configuration.xml` должно быть имя `ЛогистикаОбмен`, в `src/logistics/Configuration.xml` — `УправлениеЛогистикой`.
3. В **Summary** напишите `Подготовлена учебная логистика: JSON-обмен, оплаты и документация`. Нажмите **Commit to main** (если ветка имеет другое имя, кнопка покажет его).
4. Нажмите **Publish repository**. Имя — `logistics-1c`, описание — как выше. Для публичной публикации снимите **Keep this code private**. В поле организации оставьте личный аккаунт / `None`.
5. Нажмите **Publish Repository**, затем **Repository → View on GitHub**.
6. Проверьте на сайте: README отображается, скриншот открывается, ссылки документации работают, видны обе папки исходников и JSON-примеры. Скопируйте адрес репозитория для отправки проверяющему.

Если репозиторий с таким именем уже создан на сайте, не создавайте второй: клонируйте существующий через **File → Clone repository…**, скопируйте подготовленные файлы в его каталог, выполните коммит и **Push origin**.

## Обновления после публикации

После изменений в 1С выгружайте логистику и расширение в соответствующие отдельные каталоги, проверяйте diff в Desktop, создавайте осмысленный коммит и выполняйте **Push origin**. Не заменяйте корневую папку репозитория целиком, чтобы сохранить `.git` и документацию.

Не создавайте фиктивные коммиты с датами ранних этапов. Реальный ход разработки уже изложен в [development.md](development.md). Публикация на GitHub пока не выполнена самим подготовленным комплектом — её завершает владелец аккаунта.
