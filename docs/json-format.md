# JSON: версия 1

Файлы читаются и записываются в UTF-8. Числа передаются JSON-числами, флаги — `true`/`false`, даты — строками `YYYY-MM-DDTHH:mm:ss` без часового пояса. Незаполненная дата или ссылка экспортируется как `null`. Файлы предназначены для контролируемого обмена между двумя учебными базами.

## Логистика → Бухгалтерия

Полный пример: [Логистика_Заявка_тест.json](../examples/Логистика_Заявка_тест.json).

| Поле | Тип и смысл |
|---|---|
| `ВерсияФормата` | Число `1` |
| `Направление` | Строка `ЛогистикаВБухгалтерию` |
| `Заявка.Идентификатор` | UUID сохранённой ссылки заявки логистики |
| `Заявка.Номер`, `Заявка.Дата` | Номер и дата исходного документа |
| `Заявка.Реквизиты` | Объект со всеми пользовательскими реквизитами заявки |
| `Заявка.ТабличныеЧасти.ОтправкаДокументов` | Массив строк почтовых отправлений |
| `Заявка.ТабличныеЧасти.Дебиторка` | Массив записей работы с задолженностью |

Ссылка на справочник имеет вид:

```json
{
  "Справочник": "Сотрудники",
  "Идентификатор": "5d9169fc-b9e5-11f1-940a-b42e998097a1",
  "Наименование": "Иванов Иван Иванович"
}
```

Экспорт собирает реквизиты по метаданным. Поэтому в пакете присутствуют также расчётные поля `СуммаОплаты`, `СальдоКонечное`, `ИдентификаторЗаявкиБП` и `ДатаОбменаБП`. Приёмник Бухгалтерии их не использует как источник оплат: он переносит только согласованный список полей. Таблицы `Оплаты` и `БухгалтерскиеДокументы` в прямой пакет не включаются.

Бухгалтерия переносит номер заявки заказчика, срок оплаты, даты и пункты маршрута, суммы, признаки и ставки НДС. Для логиста, отдела, водителя, тягача и прицепа переносится только `Наименование` в строковые реквизиты расширения. UUID этих справочников в расширении не сохраняются. Организация, контрагент и договор остаются выбранными в сохранённой заявке Бухгалтерии; названия контрагента и договора из файла показываются в сообщении.

Таблицы отправки и работы с задолженностью заменяются целиком. При импорте проверяются версия и направление, корректность UUID, уже существующая связь, наличие требуемых реквизитов, заполнение организации/заказчика/договора и владелец договора. Запрос ищет дубликат связи среди других заявок, включая помеченные на удаление. Между проверкой и записью нет отдельной блокировки уникальности для параллельных сеансов.

## Бухгалтерия → Логистика

Полный пример: [БП_Результат_тест.json](../examples/БП_Результат_тест.json).

| Поле | Тип и смысл |
|---|---|
| `ВерсияФормата` | Число `1` |
| `Направление` | Строка `БухгалтерияВЛогистику` |
| `РежимПередачи` | Строка `ПолныйСнимок` |
| `ДатаВыгрузки` | Время формирования пакета в Бухгалтерии |
| `Заявка.ИдентификаторЛогистики` | UUID заявки-получателя |
| `Заявка.ИдентификаторБП` | UUID заявки в Бухгалтерии |
| `НомерЗаявкиЛогистики`, `НомерЗаявкиБП` | Строки внутри `Заявка`, для отображения |
| `СуммаЗаявки`, `СуммаОплаты`, `ОстатокКОплате` | Числа внутри `Заявка` |
| `БухгалтерскиеДокументы` | Массив связанных счетов внутри `Заявка` |
| `Оплаты` | Массив банковских поступлений внутри `Заявка` |

Строка счёта содержит `ИдентификаторБП`, `ТипДокумента`, `ВидДокумента`, `Номер`, `Дата`, `Сумма`, `Проведен`, `Комментарий`. Сейчас тип всегда `СчетНаОплатуПокупателю`. Выбираются все связанные счета без пометки удаления, в том числе непроведённые. В логистике сохраняются представление вида, номер, дата, сумма, комментарий и UUID; поля `ТипДокумента` и `Проведен` отдельно не сохраняются.

Строка оплаты содержит `ИдентификаторБП`, `Дата`, `НомерДокумента`, `Сумма`, `Комментарий`. UUID относится к банковскому документу. Если один документ содержит несколько подходящих строк расшифровки, они суммируются в одну строку оплаты для этой заявки.

### Как отбираются оплаты

Источник — `Документ.ПоступлениеНаРасчетныйСчет.РасшифровкаПлатежа`. Строка соединяется со счётом через `СчетНаОплату`; у счёта проверяется `ЛГ_ЗаявкаОснование`. У поступления должны совпадать организация и контрагент заявки, оно должно быть проведено и не помечено на удаление. Помеченные на удаление счета исключаются. Суммируется `СуммаПлатежа` подходящих строк, не весь банковский документ.

### Правила обратной загрузки

1. Версия, направление и режим передачи должны соответствовать ожидаемым.
2. UUID логистики должен совпадать с выбранной заявкой. Уже установленная связь с заявкой Бухгалтерии не может измениться на другую.
3. `ДатаВыгрузки` не может быть меньше ранее загруженной `ДатаОбменаБП`. Равная дата допускается, чтобы можно было повторить загрузку.
4. Стоимость заявки должна совпадать в обеих базах.
5. Обе таблицы должны быть массивами, UUID в пределах каждой таблицы не должны повторяться, суммы строк должны быть числовыми и неотрицательными.
6. Сумма строк оплат должна совпадать с итогом, а разность стоимости и оплат — с остатком пакета.
7. Объект в памяти заполняется и записывается один раз в конце успешного импорта. Если до записи произошла ошибка, прежние данные в базе сохраняются.

Обе таблицы полностью заменяются. Пустой массив означает отсутствие строк и очищает соответствующую таблицу; это правило следует из кода, а отдельный прогон нулевых оплат ещё нужен. Ручные строки в этих таблицах не объединяются с входящими данными.

## Ограничения протокола

- Время пакета — показание часов, не номер версии; одинаковые метки времени не разрешают конфликты автоматически. Требуются согласованные часы двух баз.
- У прямого пакета нет собственной версии изменения/даты выгрузки, поэтому защита от старого прямого файла не реализована.
- Разбор даты проверяет тип и длину, затем числовые части; это не строгий валидатор всех разделителей ISO 8601.
- Полнота и типы прямого пакета проверяются не исчерпывающе; часть ошибок обнаруживается при обращении к полям и присваивании реквизитов.
- Денежные поля 1С имеют точность 2 знака. Внешний JSON с лишними дробными знаками отдельно не нормализуется и не протестирован.
- Нет электронной подписи, очереди обмена, автоматического расписания, HTTP-сервиса, валютного пересчёта и поддержки отрицательных строк возврата.

## Согласованность приложенных примеров

Оба файла относятся к заявке `950d61e5-b9e8-11f1-940a-b42e998097a1`. В ответе одна оплата 20 000, стоимость 50 000 и остаток 30 000. В примере прямого пакета поле предыдущего обмена — 28.09.2026 13:35:08; ответ сформирован в 14:45:00. Эти файлы сохранены без изменения содержимого.
