# Руководство пользователя

## Подготовка демонстрации

Данные вымышленные. В новой базе создайте заказчика «Тестовый заказчик», его договор «Договор № 1», отдел «Отдел логистики», сотрудника «Иванов Иван Иванович» с этим отделом, водителя, тягач и прицеп. В Бухгалтерии отдельно заполните учебную организацию, банковский счёт, заказчика и договор покупателя. Их соответствие данным логистики выбирается вручную.

В логистике создайте заявку со следующими значениями:

| Поле | Значение |
|---|---|
| Дата заявки | 26.09.2026 23:51:57 |
| Заказчик | Тестовый заказчик |
| Договор | Договор № 1, владелец — Тестовый заказчик |
| Логист / отдел | Иванов Иван Иванович / Отдел логистики |
| Загрузка | 27.09.2026 09:00:00, Псков, склад заказчика |
| Выгрузка | 28.09.2026 12:00:00, Санкт-Петербург, склад получателя |
| Стоимость перевозки | 50 000 |
| Сумма исполнителя | 35 000 |
| Без НДС заказчика / исполнителя | Да / Да |
| Срок оплаты | 05.10.2026 |

При записи ожидаются суммы без НДС 50 000 и 35 000, разница 15 000. При отсутствии строк оплат остаток — 50 000. Номер нового документа определяется базой и может отличаться от примера.

## Передать заявку в Бухгалтерию

1. Сохраните и закройте заявку в логистике: обработка читает сохранённый документ, а не незаписанные изменения открытой формы.
2. Откройте обработку «Обмен JSON с Бухгалтерией» в разделе «Логистика».
3. В поле «Выбранная заявка» укажите документ. Нажмите «Выгрузить заявку в JSON» и сохраните файл.
4. В Бухгалтерии откройте «Логистика → Заявки на перевозку». Создайте документ, выберите организацию, заказчика и его договор. Запишите и закройте.
5. Откройте обработку «Обмен JSON с логистикой», выберите эту сохранённую заявку и нажмите «Загрузить заявку из JSON».
6. Выберите файл из шага 3. Заявка автоматически запишется. Кнопкой «Открыть заявку» проверьте маршрут и суммы, а также соответствие выбранных организации, заказчика и договора.

Если заявка уже связана, используйте её же. Проверка не разрешает привязать другой UUID к ранее связанной заявке и ищет уже существующую связь с исходным UUID в другой заявке Бухгалтерии.

## Создать счёт и зарегистрировать частичную оплату

1. В заявке Бухгалтерии нажмите «Создать счёт». Откроется новый счёт с организацией, заказчиком, договором и одной строкой перевозки на 50 000.
2. Проверьте счёт и сохраните его. Повторное нажатие «Создать счёт» открывает ещё один новый документ, поэтому для просмотра существующего счёта откройте список счетов.
3. Создайте «Поступление на расчётный счёт», вид операции «Оплата от покупателя».
4. Укажите ту же организацию, заказчика и договор, сумму 20 000. В поле «Счёт на оплату» выберите созданный счёт. При разбивке платежа свяжите нужную строку расшифровки с этим счётом.
5. Заполните требуемые Бухгалтерией банковские реквизиты и проведите поступление.

Кнопка «Обновить оплаты из банка» читает **уже введённые документы Бухгалтерии**. Соединение с банковским API или клиент-банком проект не выполняет.

## Вернуть результат в логистику

1. Закройте форму заявки Бухгалтерии после сохранения.
2. В обработке Бухгалтерии выберите заявку и нажмите «Обновить оплаты из банка». Ожидается: 1 документ оплаты, оплачено 20 000, остаток 30 000. Заявка записывается автоматически.
3. Нажмите «Выгрузить результат в JSON». Оплаты перед этой выгрузкой также обновляются автоматически.
4. В логистике выберите исходную заявку в обработке и нажмите «Загрузить результат из JSON».
5. Откройте заявку. В ней ожидаются один счёт, одна оплата 20 000 и остаток 30 000.
6. Повторите загрузку того же файла: сумма и количество строк должны сохраниться. Это отдельный пункт приёмочного теста.

Обратная загрузка полностью заменяет таблицы «Оплаты» и «Бухгалтерские документы». Ручные записи в этих таблицах не сохраняются. При неудаче записи файла на диск банковские данные заявки в Бухгалтерии уже могли обновиться: выберите доступный путь и повторите выгрузку.

## Окончательная оплата и отмена проведения

Создайте второе проведённое банковское поступление на 30 000 на тот же счёт. Повторите обратный обмен. Ожидаются 2 строки оплат, сумма 50 000 и остаток 0.

Для проверки удаления устаревших оплат отмените проведение второго поступления. Снова сформируйте новый обратный файл и загрузите его в логистику. Ожидаются 1 строка, сумма 20 000 и остаток 30 000. Просто повторная загрузка старого файла не получает свежие данные из Бухгалтерии.

## Отчёт «Оплата заявок»

Откройте отчёт в логистике. Установите начало 26.09.2026, конец 28.09.2026 и нажмите «Сформировать». Отчёт покажет статус оплаты, отдел, номер и дату заявки, заказчика, логиста и суммы.

Внутри запроса границы расширяются до начала и конца суток. Отбирается дата заявки, а не дата банковского платежа. Положительный остаток означает «Неоплаченные», нулевой или отрицательный — «Оплаченные»; частичная оплата относится к первой группе. Пустая ячейка остатка может быть отображением нуля.

## Если что-то не получилось

| Сообщение / ситуация | Действие |
|---|---|
| Файл относится к другой заявке | Выберите исходную заявку; не подменяйте UUID для обхода проверки |
| Этот файл старее уже загруженных данных | Сформируйте новый результат в Бухгалтерии |
| Стоимость заявки различается | Сначала передайте актуальную заявку в Бухгалтерию, затем сформируйте ответ; ранее выписанный счёт проверьте вручную |
| Нет банковской оплаты | Проверьте проведение, пометку удаления, организацию, заказчика и счёт в расшифровке платежа |
| Не настроен основной банковский счёт | Заполните реквизиты организации средствами Бухгалтерии |
| Обработка не видна в разделе | Проверьте обновление базы, перезапуск клиента и состав подсистемы; при наличии доступа откройте обработку через список всех функций |
| Старые кнопки в заявке | Для данного руководства используйте отдельную обработку; поведение сохранения у старых команд отличается |
